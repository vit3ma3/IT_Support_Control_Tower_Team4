# MoSCoW-матрица — IT Support Control Tower

**Версия:** 1.0  
**Статус:** проектная версия для согласования  
**Основание:** устав и карточка проекта IT Support Control Tower, кейс №19  
**Платформа:** 1С:Предприятие 8.3

## Назначение

Матрица фиксирует приоритеты MVP дашборда производительности ИТ-поддержки. В основу положены требования устава и карточки: синтетические данные, CSV-импорт, проверки качества, расчёты SLA и загрузки, аналитический отчёт, фильтры, визуализация, CSV-экспорт и документация. Требования, для которых исходные документы задают только направление, помечены как нуждающиеся в уточнении.

## Must have — обязательно для MVP

| ID | Требование | Критерий результата / примечание |
|---|---|---|
| M-01 | Реализовать MVP на платформе 1С:Предприятие 8.3. | Решение запускается в 1С; вариант размещения интерфейса описан в разделе «Открытое архитектурное решение». |
| M-02 | Подготовить синтетический набор не менее чем из 300 обращений. | Данные пригодны для демонстрации и не содержат реальных персональных данных. |
| M-03 | Импортировать обращения и события из CSV. | Поддерживается согласованный формат файла; точные колонки, кодировка и разделитель фиксируются в спецификации импорта. |
| M-04 | Проверять корректность загружаемых данных. | Проверяются структура и обязательные поля, хронология событий, ссылки на очередь/исполнителя/обращение, наличие SLA для приоритета, `created_at ≤ closed_at`, уникальность событий `first_response` и `resolved`. Требуется не менее пяти типов проверок. |
| M-05 | Рассчитывать время реакции и время решения. | Реакция = `first_response.ts − created_at`; решение = `resolved.ts − created_at`. Правила для отсутствующих событий и временных границ документируются. |
| M-06 | Определять нарушения SLA по приоритетам отдельно для реакции и решения. | Нарушение фиксируется при превышении целевого времени. Исходные ориентиры: P1 — 15/60 минут, P2 — 30/240, P3 — 120/480; значения хранятся как настраиваемые и подтверждаются командой. |
| M-07 | Анализировать нагрузку по очередям и исполнителям. | Базовое определение исполнителя: число активных обращений за день; активный интервал начинается с `assigned` и завершается `resolved`. Правила повторных назначений и неполных интервалов подлежат документированию. |
| M-08 | Формировать отчёт «SLA и загрузка». | Отчёт включает сводные показатели и графики SLA и распределения нагрузки. |
| M-09 | Предоставить фильтры по периоду, очереди, исполнителю и приоритету. | Выбранные фильтры применяются согласованно к показателям, детализации и экспортируемым результатам. |
| M-10 | Визуализировать соблюдение SLA и распределение нагрузки. | В базовом варианте визуализация доступна внутри 1С:Предприятие 8.3. |
| M-11 | Экспортировать агрегированные результаты в CSV. | Обязательные поля: `queue, priority, resp_avg, resolve_avg, breach_rate, load_avg`. |
| M-12 | Подготовить документацию и демонстрационные контрольные примеры. | Документированы формулы KPI, правила обработки данных и сценарий демонстрации; контрольные примеры позволяют воспроизвести расчёты. |
| M-13 | Обеспечить повторяемость импорта и расчётов для демонстрации. | Повторный импорт одинакового набора не создаёт дубликатов; расчёты сверяются с контрольными примерами. Критерий повторного импорта закреплён в уставе. |

## Открытое архитектурное решение: интерфейс

**Базовая схема:** импорт, отчёт и визуализация выполняются внутри 1С:Предприятие 8.3. Это соответствует исходному условию кейса и является вариантом, заложенным в требования MVP.

**Альтернатива:** отдельный аналитический интерфейс, работающий с выгрузкой или CSV-снимком, допустим только после согласования с преподавателем. До такого согласования команда планирует и описывает базовую схему внутри 1С. Если альтернатива будет одобрена, её границы и обмен данными нужно отразить в C4 и спецификации.

## Решения и уточнения перед фиксацией приёмки

1. Утвердить схему CSV: имена и типы полей, кодировку, разделитель, обязательность идентификаторов и правила исправления уже импортированных строк.
2. Зафиксировать календарное или фактическое время SLA, часовой пояс, правила для пропущенных событий и граничного равенства нормативу.
3. Уточнить методику загрузки для повторных назначений, открытых обращений и интервалов, пересекающих границы суток.
4. Подтвердить нормативы P1/P2/P3 как стартовые конфигурационные значения.
5. Согласовать с преподавателем отдельный интерфейс, если команда захочет отойти от базовой визуализации внутри 1С.
