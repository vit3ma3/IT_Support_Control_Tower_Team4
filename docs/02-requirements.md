## 1. Назначение

Матрица фиксирует приоритеты MVP дашборда производительности ИТ-поддержки. В основу положены требования устава и карточки: синтетические данные, CSV-импорт, проверки качества, расчёты SLA и загрузки, аналитический отчёт, фильтры, визуализация, CSV-экспорт и документация. Требования, для которых исходные документы задают только направление, помечены как нуждающиеся в уточнении.

## 3. Открытое архитектурное решение: интерфейс

**Базовая схема:** импорт, отчёт и визуализация выполняются внутри 1С:Предприятие 8.3. Это соответствует исходному условию кейса и является вариантом, заложенным в требования MVP.

**Альтернатива:** отдельный аналитический интерфейс, работающий с выгрузкой или CSV-снимком, допустим только после согласования с преподавателем. До такого согласования команда планирует и описывает базовую схему внутри 1С. Если альтернатива будет одобрена, её границы и обмен данными нужно отразить в C4 и спецификации.

Решение оформлено как [ADR-0001](adr/ADR-0001-platform-1c-only.md): статус «Принято (базовый вариант)».

## 4. Решения и уточнения перед фиксацией приёмки

1. Утвердить схему CSV: имена и типы полей, кодировку, разделитель, обязательность идентификаторов и правила исправления уже импортированных строк.
2. Зафиксировать календарное или фактическое время SLA, часовой пояс, правила для пропущенных событий и граничного равенства нормативу.
3. Уточнить методику загрузки для повторных назначений, открытых обращений и интервалов, пересекающих границы суток.
4. Подтвердить нормативы P1/P2/P3 как стартовые конфигурационные значения.
5. Согласовать с преподавателем отдельный интерфейс, если команда захочет отойти от базовой визуализации внутри 1С.

Статус каждого пункта и принятые допущения — в разделе 5.

## 6. Данные и методика расчёта

Раздел перенесён из прежнего README без потери содержания. Точная спецификация CSV, правила проверок и контрольный набор — [data/sample/README.md](../data/sample/README.md).

### 6.1. Основные сущности

| Сущность | Содержание |
|---|---|
| `tickets` | Идентификатор обращения, время создания, приоритет, очередь, исполнитель, время закрытия |
| `events` | Идентификатор обращения, тип события и временная метка |
| `sla_targets` | Приоритет и целевое время реакции и решения |

Типы событий: `assigned`, `first_response`, `resolved`.

### 6.2. SLA

```text
Время реакции = first_response.ts − created_at
Время решения = resolved.ts − created_at
Нарушение SLA = фактическое время > целевого времени
Доля нарушений = число нарушений / число обращений с рассчитанным показателем × 100%
```

Временные показатели выражаются в минутах календарного времени (ОВ-1), метки — по Москве (ОВ-2). Доли нарушений реакции и решения рассчитываются отдельно, каждая по своей выборке обращений, где показатель определён. Равенство нормативу не является нарушением. Если события нет, время не рассчитывается; если срок по нормативу истёк к концу периода отчёта — это нарушение, если нет — показатель не учитывается (ОВ-3).

Исходные нормативы для демонстрации взяты из примера кейса:

| Приоритет | Реакция, мин | Решение, мин |
|---|---:|---:|
| P1 | 15 | 60 |
| P2 | 30 | 240 |
| P3 | 120 | 480 |

### 6.3. Загрузка

Базовая метрика — число активных обращений на исполнителя за день. Активный интервал начинается с `assigned` и заканчивается `resolved`. Средняя загрузка определяется как среднее дневных значений за выбранный период. Учёт повторных назначений, незавершённых интервалов, переходов через границы суток и дней без обращений — допущения ОВ-7 и ОВ-8. Разброс нагрузки — максимальная и минимальная дневная загрузка (решение команды 17.11.26).

### 6.4. Проверки данных

1. Хронология событий обращения.
2. Наличие нормативов SLA для каждого используемого приоритета.
3. Корректность ссылок на очереди, исполнителей и обращения.
4. Условие `created_at ≤ closed_at`, когда время закрытия задано.
5. Уникальность событий `first_response` и `resolved` в пределах обращения.

Дополнительно проверяются структура CSV и обязательные поля. Ошибки отражаются в протоколе. Нумерация проверок V1–V6 и правила частичной загрузки — в [data/sample/README.md](../data/sample/README.md), раздел 4.

### 6.5. CSV-экспорт

```csv
queue,priority,resp_avg,resolve_avg,breach_rate,load_avg
```

Экспорт соответствует текущим фильтрам и значениям отчёта. Значение `breach_rate` — решение ОВ-5. Средние `resp_avg` и `resolve_avg` обязательны; медианы — S-01.

## 7. Критерии готовности к демонстрации

Перенесено из прежнего README.

- Загружается не менее 300 синтетических обращений.
- Выполняются не менее пяти типов валидаций, ошибки доступны в протоколе.
- Повторный импорт одинакового набора не создаёт дубликатов и не меняет показатели.
- Расчёты реакции, решения и SLA воспроизводятся на контрольных примерах.
- Доступны четыре обязательных фильтра, визуализация SLA и нагрузки.
- Выгрузка содержит обязательные поля и согласуется с отчётом.
- Документированы формулы, временные правила, обработка ошибок и сценарий демонстрации.
- Размещение интерфейса соответствует базовому варианту либо отдельно согласованной с преподавателем альтернативе.

Изменения обязательного объёма обсуждаются командой. Отступления от условий кейса согласуются с преподавателем.
